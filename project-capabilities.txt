SECTION 1
PROJECT OVERVIEW
----------------

* Project Name: Vibe Social Event Platform API Backend (Event Booking Backend)
* Backend Stack: 
  - Language: TypeScript / Node.js
  - Web Framework: Hono
  - Runtime Wrapper: Hono Node Server (@hono/node-server)
  - Database Client: postgres (Postgres.js)
  - ORM: Drizzle ORM
  - Schema Validation: Zod
  - Password Hashing: Argon2
  - Runner/Compiler: tsx (TypeScript Execute)
  - Third-party Integrations: Brevo Node SDK (email marketing template/webhook tracking)
* Architecture Patterns:
  - Clean Architecture / Modular Monolith structure.
  - Domain isolation: domain modules are isolated inside "src/modules" containing their own routes, controllers, services, repositories, validation logic, types, and schemas.
  - Core/Global configurations and middlewares are located in "src/config", "src/middlewares", "src/lib", "src/db", and "src/types".
  - Transactions: SQL-level database transaction blocks used for state consistency (e.g. reserving ticket slots, processing story cleanup, confirming checkout).
  - Optimistic locking: Date-trunc matching on "updatedAt" timestamps to handle concurrent write safety.
* Database: PostgreSQL (using Drizzle ORM mapping).
* Authentication Methods: 
  - JWT Session Tokens (short-lived access tokens and longer-lived refresh tokens) stored in the database.
  - Email verification with unique link tokens.
  - Multi-step signup process utilizing SMS OTP (One-Time Password) verification via Twilio Verify API (or simulated when credentials are not configured).
  - Role-Based Access Control (RBAC) middleware verifying user-tenant membership permissions.

SECTION 3
USER ACTIVITIES
----------------

A user can:
* Create a login account using email/password (`POST /auth/signup` and `POST /auth/signup/start`).
* Verify sign up code (`POST /auth/signup/verify`) and resend sign up code (`POST /auth/signup/resend`).
* Authenticate credentials (`POST /auth/login`), refresh authentication (`POST /auth/refresh`), and log out (`POST /auth/logout`).
* Retrieve personal profile properties (`GET /auth/me`).
* Request email verification link (`POST /auth/send-email-verification`) and verify email address (`POST /auth/verify-email`).
* Request verification SMS OTP code (`POST /auth/send-otp`) and verify SMS OTP code (`POST /auth/verify-otp`).
* List all active tenant organizations (`GET /tenants`) and look up individual tenant details (`GET /tenants/:slug`).
* Search and list events using parameters: venues, categories, tags, cities, dates (`GET /events`).
* View specific event details (`GET /events/:slug`), list event categories (`GET /event-categories`), tags (`GET /event-tags`), and event series details (`GET /event-series/:slug`).
* Create a booking order (`POST /booking-orders`), list orders, and cancel bookings (`DELETE /booking-orders/:orderNumber`).
* Assign attendee details to tickets (`POST /booking-orders/:orderNumber/assign-attendees`), query order items (`GET /booking-orders/:orderNumber/items`), and search order attendees (`GET /booking-orders/:orderNumber/attendees`).
* Access personal issued tickets list (`GET /issued-tickets`), view individual ticket specifications (`GET /issued-tickets/:ticketNumber`), and void/transfer tickets (`PATCH /issued-tickets/:ticketNumber`).
* Subscribe email to basic marketing distributions (`POST /marketing/subscribers`) or unsubscribe (`POST /marketing/unsubscribe`).
* Submit rating reviews and comments on organizer profile pages (`POST /organizers/:slug/reviews`), and view reviews (`GET /organizers/:slug/reviews`).
* List organizer profiles (`GET /organizers`), get details (`GET /organizers/:slug`), and search organized events (`GET /organizers/:slug/events`).
* Create personal wishlists of events (`POST /wishlists/events/:eventId`), delete from wishlist (`DELETE /wishlists/events/:eventId`), and list personal wishlists (`GET /users/me/wishlist`).
* Follow or unfollow other users (`POST/DELETE /users/:id/follow`), organizer profiles (`POST/DELETE /organizers/:id/follow`), or artists (`POST/DELETE /artists/:id/follow`).
* Search follower/following lists (`GET /users/:id/followers` and `/following`).
* Create a group plan (`POST /group-plans`), invite friends (`POST /group-plans/:id/invite`), accept/reject invitations (`POST /group-plans/invites/:inviteId/accept` or `reject`), leave groups (`POST /group-plans/:id/leave`), transfer group ownership (`POST /group-plans/:id/transfer-ownership`), view group activity logs (`GET /group-plans/:id/activity`), and get member lists (`GET /group-plans/:id/members`).
* Create group chat rooms (`POST /group-chat/rooms`), send text messages (`POST /group-chat/rooms/:id/messages`), query message history (`GET /group-chat/rooms/:id/messages`), edit messages (`PATCH /group-chat/messages/:id`), delete messages (`DELETE /group-chat/messages/:id`), react to messages (`POST /group-chat/messages/:id/reactions`), and remove message reactions (`DELETE /group-chat/messages/:id/reactions`).
* Create group decision polls (`POST /polls`), vote on poll options (`POST /polls/:id/vote`), and get poll details/results (`GET /polls/:id`).

CURRENT PRODUCT CAPABILITIES
----------------------------

Today the platform supports:
* Multi-tenant workspaces isolated by slug subdomains, scoping accounts, members, and resources.
* Comprehensive event planning setup, mapping events to categories, tags, series templates, and virtual/physical venues.
* Event ticket configurations including stock limits, booking min/max constraints, and sale windows.
* Atomic inventory checks, preventing overbooking via transactional reservations.
* Attendee profiling linked to purchased tickets, capturing name, locations, and emergency contacts.
* Physical check-in validation scans backend, verifying status, rejecting duplicate scan attempts, and registering times.
* Event-level and Tenant-level performance dashboard metrics, logging timeseries scans, check-in success logs, and revenue.
* Automated custom template styling, mailing list segment filters, duplicate functions, scheduling runs, and Brevo suppressions.
* Social follow bindings connecting users to users, organizers, and artists.
* Interactive group planning coordination: accept/reject member invites, leaving, activity logging, and transfer of ownership.
* Plan-linked chat rooms with edit tags, reply references, emoji reactions, and attachment metadata.
* Polls creation with choice option casting.
* Visual stories running for 24 hours with view logs, replies, and reactions.
* Alerts feed and channel preferences toggle dashboard.
* Organizer profiles containing ratings, reviews, social links, and organized events filters.

It does NOT yet support:
* Payment checkout processing (Stripe, credit card integration, or wallet balances do not exist in code).
* Real financial refunds (actions only toggle order/ticket status flag attributes).
* Automatic recurring events or automated story expiration (requires executing manual clean endpoints).
* Real-time messaging notifications (chat room lists use REST routes; WebSockets are missing).
* Calendar synchronization or geographical map navigation interfaces.
* Moderation queues or reporting filters for chat texts, comments, or story media.
* User blocking.
* SOS emergency panel.
* Trusted contacts alert broadcasts.
* Event helpline or medical assistance support desks.
